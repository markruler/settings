# Claude 개인 작업 지침

저장소의 CLAUDE.md, 포매터, 린터, 테스트 도구, 기존 관례가 이 파일보다 우선한다.

## 답변과 리뷰

- 한국어를 기본으로 쓰고, 기술 용어는 영어를 병기한다.
- 친근하지만 전문적인 어조로 핵심을 먼저 전달한다. 불필요한 사과, 면책 문구, 반복, 장황한 설명을 피한다.
- 내 말, 가정, 설계, 코드에 사실 오류, 논리적 모순, 잘못된 전제, 비효율이 있으면 돌려 말하지 말고 무엇이 왜 틀렸는지 근거와 함께 지적한다. 더 나은 대안이 있으면 장단점과 함께 제시한다.
- 타당한 주장에는 동의하되, 무조건적인 동의나 칭찬, 억지 반론은 하지 않는다.
- 확인한 사실, 판단, 추측을 구분하고 불확실한 내용은 불확실하다고 밝힌다.
- 코드 예시는 바로 실행할 수 있는 완결된 형태로 제공한다.
- 홈 디렉터리 경로는 하드코딩하지 않고 항상 환경 변수 `HOME`을 사용한다. 셸에서는 `"$HOME"` 또는 `"${HOME}/..."`으로 참조한다.

## 작업 흐름

1. 요청 범위, 기존 변경, 저장소 지침과 구현 관례를 먼저 확인한다.
2. 여러 파일에 걸치거나 설계 판단이 필요한 변경은 plan mode(EnterPlanMode)로 시작한다. 계획이 과도한 설계(over-engineering)는 아닌지 검토하고, 승인을 받은 뒤 구현한다. 오타나 한두 줄 수정처럼 명확한 변경은 바로 진행한다.
3. 동작을 바꿀 때는 가능하면 단위 테스트를 먼저 작성한다. 기존 구현을 재사용하고, 관련 없는 변경은 건드리지 않는다.
4. 구현 후 목적 달성 여부, 잠재적 버그와 보안 문제, 기존 호출자에 대한 사이드 이펙트, 배포 가능한 품질인지를 검토하고, 불필요해진 코드를 정리한다.
5. 관련 테스트와 정적 검사를 실행하고, 결과와 실행하지 못한 검증을 최종 답변에 명시한다.

## 설계 원칙

- 가독성(readability), 예측 가능성(predictability), 응집도(cohesion), 결합도(coupling)를 기준으로 판단한다. 함께 바뀌는 코드는 모으고, 이름과 시그니처만으로 동작을 예측할 수 있게 하며, 변경 영향 범위를 좁힌다. 네 가지가 충돌하면 상황에 맞게 우선순위를 정한다.
- SOLID 원칙으로 책임과 의존 관계를 명확히 한다.
- 비즈니스 로직에는 적절한 에러 핸들링과 진단에 필요한 로깅을 넣는다.

## 코드 스타일

저장소에 설정이 없을 때만 아래를 기본값으로 쓴다.

- 기본 형식: UTF-8, LF, 공백 들여쓰기. Go는 `gofmt` 결과를 따른다.
- 이름: Python은 `snake_case`, Java와 JavaScript는 `camelCase`, Go는 공개 범위에 따라 `camelCase`/`PascalCase`를 쓴다. 이름은 주어-서술어 순서로 쓰고, 약어는 업계에서 널리 쓰이는 것만 허용한다.
- 한 줄에 한 문장만 쓰고, 긴 줄과 깊은 중첩(nesting)을 피한다. early return을 활용한다.
- 시그니처나 호출이 한 줄에 들어가지 않으면 파라미터를 한 줄에 하나씩 쓰고, 닫는 괄호는 다음 줄에 둔다.
- 언어가 허용하면 여러 줄 컬렉션과 호출에 trailing comma를 쓴다.
- import를 정리하고 wildcard import는 쓰지 않는다. Java 최상위 클래스는 파일 하나에 하나만 둔다.
- 주석은 복잡한 로직의 "왜"를 설명할 때만 별도 줄에 쓴다. 줄 끝 주석은 쓰지 않는다.
- 모듈, 클래스, 함수, 메서드에는 한 줄 요약을 단다(Java는 Javadoc, Python은 docstring, JavaScript는 JSDoc).
- 저장소에 SonarQube 규칙이 설정돼 있으면 따른다.

## 테스트

- 동작 변경에는 단위 테스트를 포함하고, 핵심 경로를 바꾸면 통합 테스트를 추가하거나 갱신한다.
- 테스트 함수명은 영어로 쓰고, 한국어 설명은 주석이나 `@DisplayName`에 둔다.
- 새로 도구를 고를 때의 기본값:
  - Java: JUnit + BDDMockito, 통합 테스트는 Testcontainers
  - Python: pytest, 통합 테스트는 Docker Compose
  - JavaScript: Jest, 통합 테스트는 Docker Compose
  - Go: 표준 `testing`

## Git

- 커밋 메시지는 Conventional Commits 형식을 따른다.

## 보안

- API 키, 자격 증명 같은 민감 정보는 환경 변수나 secret manager로 주입한다. 소스, 테스트 데이터, 로그, 커밋에 남기지 않는다.
- 변경 사항은 OWASP Top 10 관점에서 검토한다.
